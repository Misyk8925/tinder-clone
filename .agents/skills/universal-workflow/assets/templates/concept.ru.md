# Концепт: Лимит длины био

Статус: ЧЕРНОВИК · Slug: `bio-max-length`

Нумерация разделов и FR/NFR совпадает с английской версией, если она есть.

## 1. Проблема

Владелец профиля может сохранить био длиннее 500 символов. Его нельзя быстро просмотреть; карточки в ленте переполняются.

## 2. Контракты и поведение (простым текстом)

Вход: id профиля, строка био. Выход: сохранённое био или отказ. Гарантия: био длиннее 500 символов отклоняется. Не делает: обрезку, перевод, модерацию.

## 3. Функциональные требования

| ID | Требование | Как проверяем |
|---|---|---|
| FR-1 | Отклонять био длиннее 500 символов | Native-тест: 501 символ → `BIO_TOO_LONG` |

## 4. Нефункциональные требования

| ID | Требование | Как измеряем |
|---|---|---|
| NFR-1 | Валидация p95 < 50 ms при 50 rps | Существующий API-бенч этого endpoint |

## 5. Вне рамок

- Модерация, i18n, смена лимита 500 позже

## 6. Предлагаемое решение

Предложение до gate фазы 1. База: одна проверка длины на существующем write-path профиля.

Отклонено: отдельный bio-сервис — ни один FR/NFR его не требует.
