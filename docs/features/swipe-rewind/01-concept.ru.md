# Концепт: Rewind — отмена последнего свайпа

Статус: УТВЕРЖДЁН (2026-11-25) · Slug: `swipe-rewind`

Пользователь Discover не может отменить случайный `pass` или `like`, потому что `consumer`, `deck` и `deck-read` сразу скрывают карточку. Мы добавляем `POST /api/v1/swipes/rewind` в `swipes-go` поверх append-only таблиц в `swipes_db` и локальной проекции `match.created`, публикуем компенсирующее событие `SwipeRevoked` (`tinder-contracts`) без удаления исходного свайпа, обновляем read-модели `consumer`/`deck`/`deck-read` для возврата профиля на позицию 0 и добавляем кнопку Rewind в `clients/tinder-client`.

## В скоупе

| ID | Часть | Готово, когда |
|---|---|---|
| FR-1 | Авторизованный пользователь отменяет самый последний свайп (`like` или `pass`) в течение 5 минут через `POST /api/v1/swipes/rewind` на `gateway` | Свайп ≤ 5 мин → `200 OK` (`alreadyRevoked: false`) и ровно одно событие `SwipeRevoked` в `swipe-revoked` |
| FR-2 | Повторный Rewind на тот же уже отменённый последний свайп идемпотентен, глубина отмены = 1 | Повторный вызов возвращает `200 OK` (`alreadyRevoked: true`), 0 новых событий, предыдущий свайп не откатывается |
| FR-3 | Отклонять Rewind, если с последнего свайпа прошло больше 5 минут | Свайп > 5 мин → `409 Conflict` (`REWIND_WINDOW_EXPIRED`), 0 событий |
| FR-4 | Отклонять Rewind, если последний свайп уже привёл к матчу; защищать матч при гонке | Локальная проекция матча → `409 Conflict` (`SWIPE_ALREADY_MATCHED`); `consumer` и `deck-read` не откатывают существующий матч |
| FR-5 | Отклонять Rewind, если свайпов нет или опциональный `swipeEventId` не совпадает с последним свайпом | Нет свайпов → `404 Not Found`; несовпадение `swipeEventId` → `409 Conflict` (`NOT_LATEST_SWIPE`) |
| FR-6 | Оформлять отмену append-only компенсирующим событием `SwipeRevoked` (`tinder-contracts`, ключ `profile1Id`) без удаления свайпа | Исходная запись свайпа сохраняется в `swipes_db` и `consumer_db`; JSON-контракт `SwipeRevoked` совпадает у отправителя и потребителей |
| FR-7 | Компенсировать read-модели и метрики отмен в `consumer` при `SwipeRevoked` | Пара не в матче: решение swiper'а сброшено в `NULL` в `swipe_records`, `pending_likes` обновлён (удалён отменённый like / восстановлен встречный like при отмене pass), `targetId` удалён из Redis `swipes:exists:{swiperId}`, счётчик увеличен |
| FR-8 | Вернуть профиль на позицию 0 в `deck` и `deck-read` | `deck` добавляет `profile2Id` с максимальным score в `deck:{viewerId}` + обратный индекс; `deck-read` чистит `swipes`/`repeat-candidates`, ставит приоритет `rewound` и отдаёт карточку на индексе 0 |
| FR-9 | Разрешить повторный свайп возвращённого профиля (`like` или `pass`) | Новый свайп обновляет `swipes-go`, `consumer`, `deck` и `deck-read`, сохраняя исходный свайп и `SwipeRevoked` в истории |
| FR-10 | Добавить кнопку Rewind (`rotate-ccw`, `aria-label="Rewind"`) в панель действий и экран пустой колоды в `clients/tinder-client` | `disabled`, когда недоступно/истекло/матч/в полёте; `200 OK` ставит карточку первой (или перезагружает колоду); `409` показывает toast и отключает кнопку |
| NFR-1 | Низкая задержка эндпоинта Rewind | `POST /api/v1/swipes/rewind` p95 < 150 мс при 50 rps (только `swipes_db` + Kafka produce) |
| NFR-2 | Быстрый возврат карточки в выдачу | Карточка появляется на позиции 0 в `deck-read` за < 2 с p95 при нормальном Kafka lag (< 500 мс) |
| NFR-3 | Безопасность повторов HTTP и at-least-once Kafka | 100% повторных HTTP-вызовов и дубликатов `SwipeRevoked` не создают лишних событий и не искажают read-модели |
| NFR-4 | Авторизация и rate-limit | Обязательный валидный JWT; `profile1Id` берётся строго из `sub`; на `gateway` действует `RoleBasedRateLimitFilter` (basic 100/ч, premium 500/ч, anon 0) |
| NFR-5 | Отсутствие утечек PII | 0 PII-полей (имена, email, био, JWT) в логах и заголовках `swipe-revoked.dlt` — только UUID и коды ошибок |
| NFR-6 | Обратная совместимость и ноль новой инфраструктуры | 0 breaking-изменений существующих HTTP/Kafka-контрактов; 0 новых сервисов, БД и брокеров |

## Вне скоупа

| Что | Почему |
|---|---|
| Отмена глубже 1 свайпа подряд | В v1 отменяется только самый последний свайп |
| Отмена матча (`unmatch`) и удаление чата | Свайпы с матчем отклоняются с `409 Conflict` |
| Premium-гейт, биллинг, дневные квоты | Решение владельца Q1: доступно всем авторизованным с rate-limit на Gateway |
| Новая таблица пользовательских счётчиков свайпов в `consumer` | Решение владельца Q3: компенсируем существующие read-модели и метрики |
| Изменение схем `swipe-created`, `swipe-saved`, `match.created` | Существующие межсервисные контракты сохраняются без изменений |
| Деплой в production | Доставка ограничена кодом, миграциями, контрактами и тестами в репозитории, пока деплой не запрошен |
